## 项目定位

这是一个**单店、局域网、自部署**的美发店客户管理系统。目标是让老板和店员在 Windows 11 / macOS 电脑以及手机浏览器上快速完成客户、消费、充值和基础经营管理。

### 核心原则

- MVP 优先，不做大而全 ERP。
- 单体 Go 服务 + Vue 前端，降低部署和维护成本。
- SQLite 作为第一阶段数据库；未来多店/云端再迁移 PostgreSQL。
- 手机端采用响应式 Web，不开发原生 App。
- 业务数据可追溯，余额/充值/消费必须通过流水和事务保证一致性。
- 不为了“企业级”提前引入 Redis、Kafka、微服务、K8s。

```
├── .ai/                       # 设计文档体系（本目录）
├── server/                    # Go 后端（单体，含静态文件托管）
└── web/                       # Vue 3 前端源码，构建产物输出到 server 可访问的 web/dist
```

## 部署目标

服务器运行于店内一台 Mac 或 Windows 11 电脑，构建后部署目录：

```
hair-salon/
├── hair-salon-server(.exe)    # 单一可执行程序（后端 + 静态文件托管）
├── web/dist                   # 前端构建产物（由 server 托管）
├── data/
│   ├── hair-salon.db          # SQLite 数据库（仅本机磁盘）
│   ├── backups/
│   └── uploads/
├── logs/
└── config.yaml
```

默认监听 `0.0.0.0:8080`。

电脑访问 `http://localhost:8080`，手机通过店内 Wi-Fi 访问 `http://局域网IP:8080`。

数据库仅存服务器本机磁盘，禁止在 SMB/NFS 网络共享目录直接运行 SQLite。

## MVP 范围

1. 登录与角色权限
2. 客户管理、搜索、标签、详情
3. 服务项目管理
4. 消费订单及明细
5. 充值、余额流水
6. 员工管理
7. Dashboard 基础统计
8. 操作日志
9. 数据备份与恢复
10. 系统设置（门店名称、积分比例）
11. PC + 手机响应式体验

## 暂不做

微信营销、短信、小程序、预约排班、库存、供应链、复杂财务、多门店、AI、云同步。

## 关键架构决策

### 为什么 SQLite

单店局域网、10～30 个同时在线客户端、业务写入量有限，SQLite 足够且部署成本最低。启用 WAL 和 busy_timeout，所有重要写操作使用事务。

### 为什么单体

当前业务边界清晰，拆微服务会增加部署、调试和数据一致性成本。Go 单体服务已经能满足目标规模。

### 为什么 Vue 响应式 Web

店员需要手机临时操作，但没有必要承担 App 开发和发布成本。

## 非功能要求

- 支持 Windows 11、macOS。
- 数据库和上传文件可备份。
- 密码禁止明文存储。
- 所有管理员危险操作有日志。
- 余额不得被普通 CRUD 直接修改。
- 关键接口幂等/防重复提交。
- 后端 `go test ./...`，前端 `npm run build` 必须通过。

## 成功标准

老板拿到一台电脑，启动程序；店员连接店内 Wi-Fi 后即可用手机打开系统，完成“搜索客户 → 查看历史 → 消费/充值”的完整闭环，无需安装额外服务。
