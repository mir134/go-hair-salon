# 设计目标

PC 用于后台管理，手机用于店内快速操作。优先保证少点击、快速找到客户、快速完成消费/充值。

# 1. 页面结构

- 登录
- 首页 Dashboard
- 客户管理：客户列表、客户详情、新增/编辑客户
- 消费管理：新建消费、消费详情
- 充值管理：新建充值、充值详情
- 服务项目：分类、服务列表
- 员工管理
- 标签管理
- 操作日志
- 系统设置
- 备份恢复

# 2. PC 导航

左侧主导航：Dashboard / 客户 / 消费 / 充值 / 服务 / 员工 / 日志 / 系统。

顶部区域：当前用户、门店名称、退出登录。

导航按角色显示：

- staff 仅显示：Dashboard / 客户 / 消费 / 充值。
- admin 额外显示：服务 / 员工 / 日志 / 系统。

不通过前端隐藏按钮代替权限控制（后端为最终边界），但隐藏与角色无关的菜单是允许的导航简化。

# 3. 手机端核心路径

查询客户：搜索手机号/姓名 → 客户结果 → 客户详情。

快速消费：客户详情 → 快速消费 → 选择服务 → 确认金额/支付方式 → 完成。

快速充值：客户详情 → 充值 → 输入实付金额/赠送金额 → 选择支付方式 → 确认 → 完成。

挂单：客户详情 → 快速消费 → 选择服务 → 挂单（开单不收款）；之后从「待结账」入口结账。

手机端首页优先提供：搜索客户、最近客户、快速消费、快速充值。

# 4. 客户详情

必须显示：姓名、手机号、标签、余额、积分、累计消费、最近到店、最近消费、消费记录、充值记录、余额流水、积分流水。

# 5. 消费页面

选择客户 → 选择服务 → 自动带出标准价格 → 选择支付方式 → 选择员工 → 确认消费。

支持两种完成方式：

- 直接完成：确认收款后立即完成订单。
- 挂单：先开单不收款（订单状态为「待结账」），之后在消费列表/客户详情中结账。

待结账订单显示「待结账」标识，提供结账入口（选择支付方式 → 确认收款）。

挂单明细编辑：待结账订单可进入编辑，增删服务项目、修改数量；确认后订单金额重算。修改单价仅 admin 可操作（staff 价格输入禁用）。

确认前显示：服务、原价、成交价、支付方式、操作员工、总金额。

改价/折扣规则（对应 06-BUSINESS-RULES.md 3.1）：

- admin 可修改本次成交价格（改价/折扣），修改时必须填写原因。
- staff 不可修改成交价格，仅按标准价成交，界面上价格输入框禁用或隐藏。

# 6. 充值页面

输入：实付金额、赠送金额、支付方式、备注。

确认前显示：实付 + 赠送 = 增加余额。

禁止把赠送金额误显示为客户实际支付金额。

# 7. Dashboard

MVP 显示：今日营业额、今日消费单数、今日充值金额、今日新增客户、今日消费人数、待结账单数、最近消费、最近充值。

统计必须显示统计日期范围。

待结账单数为当前实时数据，不受日期范围影响。

# 8. UI 原则

- PC 使用 Element Plus。
- 手机使用响应式布局，按钮适合手指点击。
- 表单错误就地提示。
- 危险操作二次确认。
- 金额统一显示两位小数。
- 空数据提供明确空状态。
- 加载状态明确。
- 网络失败可重试。
- 不通过前端隐藏按钮代替权限控制。

# 8.1 系统设置页

仅 admin 可见（对应 04-API.md Settings 段）。

MVP 包含：

- 门店名称（顶部显示，对应 settings.shop_name）。
- 积分比例：每消费 1 元获得积分（对应 settings.points_per_yuan）。

交互：

- 修改必须二次确认。
- 修改成功提示，顶部门店名称即时更新。
- 修改操作写 operation_logs。
- 新比例仅影响之后产生的消费积分，不追溯历史。

# 9. 关键交互原则

- 客户搜索优先手机号。
- 客户详情是店员日常工作的核心页面。
- 消费和充值尽量 3～5 步完成。
- 成功后明确显示结果和最新余额。
- 账务类操作成功后禁止静默失败。
- 手机端不要堆复杂表格，使用卡片/列表/抽屉/弹窗。
